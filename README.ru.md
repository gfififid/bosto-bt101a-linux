# Драйвер Bosto BT-101A для Linux

[English documentation](README.md)

Экспериментальная поддержка USB-планшета **Bosto BT-101A Touch**. Программа
передаёт JPEG-кадры контроллеру RacerTech MI8808 и через EVDI создаёт обычный
DRM-монитор для рабочего стола.

| Компонент | USB ID | Поддержка |
| --- | --- | --- |
| Экран | `34c7:2700` | Рабочий стол и тестовая картинка `1280×800` |
| Перо | `0ed1:7821` | Штатный Linux HID; включена точечная поправка координат |
| Тач | `34c7:2700`, интерфейс 1 | Штатный Linux HID; включён помощник привязки к экрану в KDE |

Проверено на Fedora 44, KDE Plasma Wayland, x86-64, ядро
`7.3.0-4.cachyrt1.fc44.x86_64`. В аппаратном тесте получено до **59,4 обновления/с**
при цели 60 кадров/с. Проверены координаты пера, нажим, рисование и привязка тача.
Другие дистрибутивы, архитектуры и ревизии Bosto требуют отдельной проверки.
Сейчас поддерживается один подключённый экран.

## Сборка

Нужны компилятор C, Make, pkg-config, пакеты разработки libusb 1.0,
libjpeg-turbo и libdrm, Python 3 и заголовки именно запущенного ядра.

Зависимости пользовательской части для Fedora:

```bash
sudo dnf install gcc make pkgconf-pkg-config libusb1-devel libjpeg-turbo-devel libdrm-devel
```

Отдельно установи соответствующий пакет разработки ядра. Для нестандартного
или RT-ядра нужен пакет devel той же сборки. Должен существовать каталог
`/lib/modules/$(uname -r)/build`.

```bash
make -j4
make module -j4
make test
```

Исходники EVDI включены с зафиксированной ревизией; сборка не загружает их из
сети. `make module` собирает модуль под текущее ядро. При необходимости компилятор
можно заменить, например `make CC=clang`.

## Первая аппаратная проверка

Из каталога проекта:

```bash
sudo ./build/bosto-display --probe
sudo ./build/bosto-display --pattern
```

`--probe` читает статус и EDID, `--pattern` передаёт цветные полосы `1280×800`.
Сообщение об успешной передаче подтверждает USB-операцию; изображение нужно
проверить на самом планшете. Модуль EVDI для этого теста не требуется.

## Ручной запуск

```bash
sudo ./run-display.sh
```

Скрипт при необходимости загружает локальный модуль EVDI подходящего ядра и
запускает передачу изображения. Если новый монитор `DVI-I-1` не включился
автоматически, включи его в настройках экрана. Команда должна оставаться
запущенной; Ctrl+C завершает её и отключает виртуальный монитор.

По умолчанию цель — 60 кадров/с, качество JPEG — 90. Частота режима 60 Гц в KDE
и число новых кадров, передаваемых через USB, — разные измерения.

```bash
sudo ./run-display.sh --fps 60 --stats
```

Для измерения двигай окно или рисуй. Каждые две секунды `--stats` показывает
updates/s, поток JPEG и время захвата, кодирования и USB. На неподвижном рабочем
столе мало обновлений или `idle` — нормальное поведение. Заданная частота служит
верхним пределом, а не гарантированной скоростью.

## Автозапуск

После успешной ручной проверки и сборки:

```bash
sudo ./scripts/install.sh --autostart
```

Установщик копирует программу, библиотеку EVDI и модуль текущего ядра в
принадлежащий root каталог `/usr/local/lib/bosto-display`. Systemd и udev
запускают службу для нужного USB-устройства при загрузке компьютера или
подключении планшета, а при отключении останавливают её экземпляр. При следующих
автоматических запусках терминал и ввод пароля не требуются. Перед установкой
останови вручную запущенный драйвер, чтобы два процесса не заняли один интерфейс.

Для дополнительной регистрации включённого модуля EVDI в DKMS, если DKMS
установлен и нет конфликтующей регистрации EVDI:

```bash
sudo ./scripts/install.sh --autostart --dkms
```

Без DKMS после обновления ядра нужны пересборка и переустановка. Для DKMS также
нужны заголовки каждого нового ядра. Автоматическая подпись модулей для Secure
Boot в этот проект не включена.

Подготовить дерево установленных файлов без изменения служб системы:

```bash
./scripts/install.sh --destdir ./build/stage --autostart
```

Удалить установленный экранный драйвер и службу:

```bash
sudo ./scripts/uninstall.sh
```

Поправка координат пера по умолчанию сохраняется. Её отдельный откат описан ниже.

## Координаты пера и привязка тача

У исследованной ревизии BT-101A Stylus Linux объявляет неверный максимум X
`8191`, хотя активный отчёт использует `17920`. Общая системная hwdb для другой
модели Bosto может дополнительно задавать неверный физический размер пера.
Для исследованной ревизии:

```bash
sudo ./fix-pen.sh
```

Скрипт проверяет отпечаток HID-описателя и устанавливает
`/etc/udev/hwdb.d/99-bosto-bt101a.hwdb`. Только нужная коллекция Stylus получает
X `0..17920`, Y `0..10240` и разрешение `83/76` единиц/мм. Нажим и отдельная
коллекция Pen с отчётом `0A` не меняются. Затем переподключи планшет, чтобы
libinput и рабочий стол заново открыли устройство с правильными параметрами.

Откат: `sudo ./fix-pen.sh --undo`, затем ещё одно переподключение.

В KDE Plasma Wayland, после включения экрана, выполни от пользователя рабочего
стола **без sudo**:

```bash
python3 tools/map_inputs.py --apply-touch --reset-pen-area
```

Помощник привязывает только известные перо и тач к `DVI-I-1` и задаёт перу полную
область монитора. Если имя выхода отличается, используй `--output ИМЯ`.
Перед изменениями сохраняется резервная копия; `--restore BACKUP_JSON`
восстанавливает затронутые настройки. Для других рабочих столов нужны их
собственные инструменты привязки устройств.

## Диагностика и ограничения

```bash
python3 tools/diagnose.py
python3 tools/calibrate_pen.py --show
python3 tools/inspect_pen.py --seconds 20
```

Эти команды читают сведения об устройствах или короткий поток событий только
планшета. Диагностика исключает клавиатуру и серийные номера. Явные действия
`--apply`/`--restore` у помощника калибровки предназначены для временной поправки
осей с резервной копией; постоянное решение — `fix-pen.sh`.

Поддерживаются 32-битные XRGB/ARGB-буферы и размеры в пределах панели, кратные
16×8 пикселям. Проверенный режим по умолчанию передаёт полные кадры.
`--damage` включает экспериментальные частичные обновления; на реальном экране
эта опция ещё не проверена. Яркость, звук, DDC/CI, suspend/resume и другие модели
не реализованы или не проверены. При USB-ошибке программа завершается;
автозапуск создаёт новый экземпляр службы для вновь подключённого устройства.

Протокол и отпечатки установщиков описаны в [PROTOCOL.md](PROTOCOL.md).
В репозитории должны храниться исходники; сборки и личные диагностические
резервные копии не следует добавлять в коммиты.
